# 快乐能源联机游戏运行与操作说明

本文档说明如何在本机或局域网中启动“快乐能源”联机游戏，并给出主持人和玩家的完整操作流程。

## 1. 运行环境

- Node.js 20 或更新版本。
- 同一个局域网内的手机、平板或电脑浏览器。
- 无需数据库；游戏状态保存在服务端内存中，关键变更会写入 JSON 快照。

## 2. 安装与启动

在项目根目录执行：

```bash
npm install
npm start
```

启动成功后，终端会显示类似地址：

```text
本机:   http://localhost:3000
局域网: http://192.168.x.x:3000
```

- 主持人电脑使用 `http://localhost:3000/host/`。
- 玩家手机访问终端中显示的“局域网”地址，或扫描主持大屏上的二维码。

默认端口是 `3000`。如需修改，编辑 `data/config.json` 中的 `port` 后重新启动。

## 3. 结束服务

在运行 `npm start` 的终端窗口按 `Control + C`。终端回到命令行后，服务已结束。

如果服务在后台运行，可先找到占用端口的进程再结束它：

```bash
lsof -nP -iTCP:3000 -sTCP:LISTEN
kill <进程ID>
```

## 4. 主持流程

1. 打开 `http://localhost:3000/host/`。
2. 输入主持人称呼，选择队伍数，范围是 2 到 8 支队伍。
3. 点击“创建房间”，大屏会显示房间码和玩家加入二维码。
4. 等待玩家加入并选择队伍、角色。每队标准配置为 7 人：
   - 新能源发电企业
   - 电网企业
   - 新能源汽车企业
   - 智能建筑企业
   - 智能材料企业
   - 发改委
   - 自强城城长
5. 开局前可在主持台大厅点击“添加队伍”，或移除没有成员的空队伍。队伍范围为 2 到 8 队；移除后系统会自动重排队伍编号。
6. 每队第 8 名成员可以担任首席精算师；精算师与发改委同分，不计入团队总分。
7. 各队 7 个标准角色齐全后，点击“开始游戏”。如有队伍缺员，主持人可以使用“缺员强制开始”。
8. 在目标卡阶段，等待每队城长在玩家端保留 1 张目标卡。目标卡候选和保留结果全场公开。
9. 点击“进入第1轮规划”。默认规划时间 15 分钟，系统会同步倒计时。
10. 规划期间，大屏只显示每队每个角色的“锁定、考虑中、放弃、未选择”进度，不显示具体行动草案。
11. 规划结束后，主持人点击“开始第1轮结算”。系统会先进行服务端骰子判定，再逐步展示发电、消耗、储能、弃电和资金结余。
12. 第 1 轮结算和排行榜展示完成后，点击“进入第2轮规划”。
13. 第 2 轮规划与结算流程与第 1 轮一致，但每名角色不能重复第 1 轮已选行动。
14. 第 2 轮结算后进入终局颁奖页，可导出 JSON 和 CSV 成绩。

## 5. 玩家流程

1. 打开主持人提供的局域网地址，例如 `http://192.168.x.x:3000/`。
2. 输入 4 位房间码和昵称，点击“加入游戏”。
3. 在大厅中选择自己的队伍和角色。同一队同一角色只能由一名玩家担任。
4. 进入目标卡阶段后，本队城长会看到两张公开候选卡，并选择 1 张保留。其他队员可以查看候选和结果，但不能选择。
5. 进入规划阶段后，每名角色从自己的行动卡中选择 1 项；产学研大突破事件下，材料企业可以同时执行 2 项研发。
6. 玩家界会实时显示资金结余和输配上限。若行动耗电量大于输配上限，或资金、土地不足，系统会标出原因并禁止提交。
7. 确认行动后点击“锁定行动”。锁定前可以继续修改；也可以选择“放弃行动”。
8. 城长在规划阶段可以使用市长特批权：
   - 指定 1 项行动减免 5 资金；
   - 或允许全队超支 5 点以内。
   每轮只能使用一次。
9. 结算阶段，玩家会看到本队骰子结果、结算步骤和排行榜。
10. 第 2 轮行动选择时，系统会自动阻止与第 1 轮重复的行动。
11. 终局后，玩家可以看到本队个人分、团队总分、目标卡达成情况和全场排名。

## 6. 核心限制与结算规则

- 每名标准角色每轮选择 1 项行动，两轮不得重复；可以声明放弃。
- 每轮资金为 100 单位，未用完清零；事件、政策和特批会影响当轮可用资金。
- 全队两轮共用 12 单位土地。
- 输配上限初始为 3 点；扩建智能电网永久增加 4 点，柔性电网调度当轮增加 2 点。
- 单步行动的耗电量大于当前有效输配上限时，该行动不能执行。
- 储能上限初始为 2 点；储能电站、车网互动 V2G 等效果会增加容量。
- 结算顺序为：发电产出、实际消耗、储能蓄水、弃电罚分、个人分、团队总分。
- 第 2 轮可使用第 1 轮结存的储能电量。
- 弃电罚分默认每点 2 分；现货电价暴涨事件下提升为每点 4 分。

## 7. 断线、刷新与恢复

### 玩家刷新或断线

玩家端会将会话凭证保存在浏览器标签页的 sessionStorage 中。如果页面刷新或短暂断线，通常可以在同一标签页中自动恢复；Socket.IO 也会尝试自动重连。

如果重新打开新标签页，sessionStorage 不会共享，需要重新加入房间。

### 主持人恢复房间

服务端会在关键状态变化时把房间快照写入：

```text
data/snapshots/<房间码>.json
```

服务重启后，主持人在 `/host/` 页面点击“恢复上次房间”，即可通过浏览器中保存的主持人凭证恢复房间。若浏览器凭证已丢失，无法凭空恢复主持人会话。

## 8. 成绩导出

终局后，主持台提供两个导出入口：

- JSON：完整房间状态和结算明细；
- CSV：队伍个人分、储能、罚分、目标卡、总分和名次。

导出文件也会写入：

```text
data/exports/
```

## 9. 运行测试

在项目根目录执行：

```bash
npm test
```

测试覆盖规则数据、成本管线、行动校验、随机数、轮结算、计分排名、目标卡、事件卡、房间管理、快照恢复、状态机和端到端剧本。

## 10. 常见问题

### 玩家无法访问局域网地址

确认手机与主持人电脑连接同一个 Wi-Fi，确认防火墙允许 Node.js 监听端口，并使用服务启动时打印的局域网地址，而不是 `localhost`。

### 提示端口被占用

默认端口 `3000` 已被其他程序使用。关闭占用程序，或修改 `data/config.json` 中的 `port` 后重新启动。

### 结算被阻止

服务端会在结算前重新校验全部已锁定行动。若存在超支、超用土地或超过输配上限，主持人会在大屏看到违规原因，可将违规角色强制置为放弃后再结算。

### 需要清理运行数据

快照和导出文件分别位于 `data/snapshots/` 与 `data/exports/`。删除对应房间文件即可移除历史恢复数据；请勿删除 `data` 目录下的规则配置 JSON。
